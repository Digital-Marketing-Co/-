# /pe — Production Engineering and Visual Excellence

## Invocation
/pe [objective, image, app, page, or artifact]. Respect the user's explicit deliverable: image generation, specification-only, code, or deployment. Do not substitute a decorative rendering for requested functional code or vice versa. /p means continue authorized work, not invent credentials or bypass external approvals.

## Process
1. Resolve goal, existing source of truth, audience, constraints, output medium, and acceptance criteria. Reuse established repo implementation and components before adding new frameworks. Preserve original supplied images for edits unless regeneration is requested.
2. Prompt-engineer for precise, photorealistic and contextually relevant output where images are requested: 9:16 iPhone wallpapers or 16:9 banners as applicable, nonduplicated imagery, physically plausible lighting, accurate text or no text, depth/occlusion, and subject-safe crops. Invoke /parallax when requested; do not claim a still image has functional gyroscope motion.
3. For web apps, prefer Next.js App Router, React, TypeScript strict, Tailwind CSS, Prisma ORM when a database is justified, and deployable Vercel architecture. Choose newer alternatives only when supported by evidence. Favor deterministic parsing/templates/indexing over paid AI inference, with zero runtime LLM credit consumption where required.
4. Futuristic aesthetic: responsive translucent panels, subtle aurora/glow, realistic layered backgrounds, accessible high-contrast typography, tasteful depth, smooth transitions, and user-selectable reduced motion. Prioritize readability over decoration; no overlapping or overflowing content.
5. Build semantic HTML, keyboard access, focus indicators, descriptive alt text, reduced-motion handling, touch targets, and WCAG 2.2 AA targets. Provide secure-by-default authentication, authorization, secrets handling, validation, and error boundaries where relevant.
6. Implement SEO/AIO/GEO/AEO appropriately: metadata, canonical links, structured data, sitemap, accessible content, and social previews. Never assert audit scores without executing the actual auditor.
7. For Digital Marketing Co. Free Website Auditor work, inspect the current authoritative repository path app/free-website-auditor and published website; map checks only when definitions are available. Distinguish passed, failed, unavailable, and inapplicable checks. Do not fabricate totals.
8. Use /ITQE and /latex for equations when available; verify formulas and renderability. Apply site-wide /copyright and branding standards only when relevant to the artifact.
9. Iterate technical, accessibility, security, visual, responsive, content, and performance QA. Fix reproducible failures, retest, and stop after two consecutive full passes show no material improvement or when blocked by tool access. Never claim an unrun test, commit, push, or deployment succeeded.
10. If asked to commit or deploy, inspect the repository state, make minimal scoped changes, verify build/test results where possible, and report actual commit/deployment identifiers. Never expose or hardcode credentials.

## Output
Deliver the requested real artifact (image, code, specification, or verified URL) plus concise implementation/QA status and unresolved limitations. Keep generated images distinct from executable software. For extensive documents, respect the requested /4629, /banner, /images, /textbook, and /expound workflows when available.
