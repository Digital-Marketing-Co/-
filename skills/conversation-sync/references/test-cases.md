# Required Test Cases

| Test case | Required result |
|-----------|-----------------|
| Timing and precision | Fake-clock tests verify 5,999 seconds, exactly 6,000 seconds, and subsecond activity near the boundary. A new interaction before final verification supersedes the prior deadline. |
| Activity evidence | Out-of-order arrivals, duplicated events, future timestamps, failed freshness reads, and in-progress replies cannot cause premature live delivery. Repeated observation of one revision does not move its estimated deadline. |
| Late activity | A change discovered during a write produces a truthful receipt for the delivered revision and a separate queued revision. |
| Discovery and scope | Global and project-only inventories reconcile across pages. Multiple project memberships survive. Partial coverage stays visible. Cross-account records stay isolated even with identical provider IDs. |
| Source and destination identity | Replaying exports, rerunning jobs, reopening an existing ChatGPT chat, and changing worker versions do not duplicate conversations. Older snapshots cannot overwrite newer verified revisions. Ambiguous ID-less matches stay unresolved. |
| Crash recovery | Test a crash before cursor commit, lease expiry, simultaneous workers, a confirmed write followed by a crash before receipt persistence, and an ambiguous destination timeout. No blind retry follows an uncertain write. |
| Files and project enrichment | Test partial retrieval, delayed bytes, identical bytes with different names, revoked access, failed integrity verification, and project membership changes. A metadata refresh cannot reveal an ineligible revision. |
| Per-project instruction capture | Enumerate instruction-bearing and empty projects, duplicate names, inaccessible settings, omitted export fields, and scoped rules. Verify original text, project identity, revision, and provenance. |
| Project instruction installation | Verify that instructions are saved in the correct ChatGPT project before the first live chat delivery. Test a project with no chats, renames, a verified read-back, a write retry, and instructions that exceed destination limits. |
| Project instruction conflicts | An older snapshot cannot overwrite a newer verified instruction revision. Test destination edits, conflicting many-to-one mappings, an authoritative clear, a partial export, and a shared project with a broader audience. Manual staging and file uploads leave installation unverified. |
| Routing and account changes | Every new authorized provider inherits the selected ChatGPT destination. An outage, disconnected account, changed workspace, or revoked authorization leaves items pending for the intended scope. |
| Fallback and partial delivery | Exercise native receipt, verified reference delivery, manual upload pending, snapshot-only eligibility, and partial package receipt. Count each outcome correctly. |
| Per-conversation GitHub timing | Push one standalone conversation and one project conversation at their own 6,000-second deadlines. A newer message delays only its own chat. A conversation found in global history and multiple projects yields one revision record with all links. |
| GitHub push and recovery | Verify the remote commit and manifest after successful pushes. Test timeout after remote success, branch conflicts, concurrent writers, protected branches that require a merge, and duplicate replay. A staged file or open PR stays pending. Verify that a dry run leaves the GitHub branch unchanged. |
| Destination independence | With ChatGPT or project settings unavailable, the approved GitHub push still proceeds. With GitHub unavailable, eligible ChatGPT delivery still proceeds. Retrying either destination preserves the other’s receipt. |
| Repository release and rollback | Test forged or replayed events, delayed older commits, failed builds, missed notifications, rollback with pending jobs, and state compatibility across versions. |
| Discovery drift and integration routes | A newly listed client remains disabled until authorized. Verify each claimed live GitHub, Vercel, history, and ChatGPT destination capability separately. Cover a direct integration, an indirect deployment route, and work-record-only access. |
| Data boundaries | Confirm dry-run produces no writes or live cursor changes. Verify that untrusted source content cannot issue commands and that live records and sensitive filenames are absent from skill release history and operational logs. Verify conversation archive access, encryption or explicitly authorized plaintext, file references, and repository/branch isolation. |
