# GoOn — Continue Until Verified Complete

## Canonical invocation
`GoOn` or `Go` expands exactly to:

> D P u C

## Execution semantics
- **D**: Apply the existing /disabled autonomous, accessibility-first continuation workflow to the active user-authorized task.
- **P**: Apply /Perfect improvements, quality controls, and relevant /God safeguards.
- **u**: Continue **until** the explicit completion criteria are met, using bounded, nonrecursive iterations.
- **C**: Invoke the existing /Complete verification gate. Output exactly `Complete` only when every applicable criterion is evidenced as passed.

Resume the active task from its verified checkpoint; preserve user intent, previously approved constraints, and evidence. Do not restart completed steps, fabricate progress, or silently shorten the task.

## Safety and termination
Never recursively invoke GoOn, /disabled, /Perfect, or /Complete. Work within available tool and execution budgets; stop with precise outstanding steps and blockers when the task cannot be finished. Respect repository concurrency checks, approvals, credentials, privacy, security, copyright, accessibility, QA, visual QA, and /karma records as applicable. Do not claim background operation, deployment, successful tests, exhaustive coverage, or completion without independent evidence.

## Compatibility
GoOn/Go is a new distinct command and does not replace /Final (F/f), /Finish, /sync, or existing skill aliases.
