# Adapter and renderer handoff

Run `scripts/atlas_to_deep.py atlas.json --out deep.json` to validate and adapt supplied material. Run `scripts/build_atlas_pdf.py atlas.json --out YYYY-topic-slug-wca-atlas.pdf` to write `deep.json` beside the source and invoke the existing deep renderer with the required output argument. The wrapper prefers the adjacent reviewed deep skill; it uses the shared frontmatter resolver only when that renderer is absent. Missing scripts or dependencies fail the build.

Title, author, date, abstract, keywords, house fields, notes, and original sections carry through. Original node, gazetteer, and connection records remain available in the adapted JSON. The adapter adds a reference-system section and labelled node, gazetteer, and connection sections before notes and bibliography. It adds those back-matter sections when arrays exist but their section declarations are absent. Supplied structured bibliography entries retain their full form in `atlas_bibliography`; their `text` fields become the deep renderer's bibliography strings. Source image paths become absolute paths so relocation of adapter output does not break them. The source JSON is preserved.

The builder does not research, generate imagery, perform geographic transforms, create cartographic panels, or certify citation evidence. Deep supports supplied section banners and equation objects; other section fields remain stored but are not automatically drawn. Added inventory sections receive no automatic artwork. Prepare any required maps and banners as separate verified assets, then inspect the rendered PDF. Compilation alone does not complete visual or evidence review.
