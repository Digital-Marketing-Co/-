# Shared document update protocol

Apply to the current deliverable only. Skill maintenance does not itself request a book, translation, or image. Explicit user instructions and platform rules prevail. Read this once per run; it is a shared reference, not a recursively invoked skill.

Use a durable graph/ledger for substantive multi-phase production. For a design-only first response, read-only evaluation or small utility, retain a lightweight in-context plan and do not write ledger files or execute production scripts merely to present a question. User-requested source preservation determines artwork density; house cadence applies only when the selected design contract calls for it.
Normalize aliases before planning: pe/PromptEngineer → prompt-engineer; wca-ivy-biblio/ivy-biblio → academy-ivy-biblio; 6429 → 4629. Resolve installed skills by frontmatter, not assumed folder names. Maintain one run ID, document ID, immutable revision, requirement ledger, source registry, brief, and execution ledger across handoffs.
Use scripts/plan.py in the book package to canonicalize known aliases and order explicitly declared dependency edges. Resolve actual installed packages separately by frontmatter; the planner does not discover packages or execute phases. Read required workflows once. Register each operation by (run, document, revision, canonical skill, phase, input digest, options digest, language/output scope). States are pending/running/done/failed/blocked. Reuse completed matching operations; never invoke a running operation recursively. One canonical skill node may expose several phases; validation after a material update is a new operation, not a duplicate top-level invocation. Different translation/output scopes are distinct legitimate operations. Resume failed work without repeating successful research, intake, asset generation, or paid calls. A detected dependency cycle requires a phase handoff, never recursive dispatch. Quoted slash tokens in source material are protected content unless separately authorized for execution.

## Update transaction
For every addition, deletion, move, translation, evidence change, style change, or optimized export:
1. Snapshot source and record changed object IDs and input hashes. Map every user clause and answer to acceptance evidence.
2. Revise the manuscript and reconcile claims, continuity, headings, artwork, equations, tables, cross-references, language alignment, and source identities.
3. Invalidate affected content and layout checks, globally invalidate citation order, contents, pagination, and final-export checks. Never reuse a PASS against changed inputs.
4. Rebuild citations across the ENTIRE final reading order, including captions, tables, footnotes and appendices. Recompile; render and inspect; repair and repeat affected checks.
5. Record defect ID, severity, location, cause, repair, regression evidence, revision and final file hash. Use PASS/FAIL/BLOCKED/NOT TESTED/NOT APPLICABLE with reasons. An automated text scan never substitutes for visual inspection.

## PDF-first evidence and citation integrity
For added factual claims, seek relevant authoritative primary PDFs: original research, systematic evidence, official datasets, standards, and issuing institutions. Authority means claim-relevant expertise and methods, not prestige alone. Open and read each cited source; verify title, authors/institution, date/version, DOI where present, canonical landing URL, accessible PDF URL, actual page/section, retrieval date, and supporting passage. Record unavailable PDFs and any justified non-PDF exception. Never fabricate sources, locators, access, or support. Fictional story events need no invented scholarly citations; research factual foundations and label fictionalization.
Use immutable work IDs and citation-event IDs. Deduplicate identical works by verified identity while keeping distinct editions distinct. For Chicago notes, assign note EVENTS 1..N in reading order, including separate shortened notes on repeat works; order the unique-work bibliography by first appearance. For numeric work-reference styles, assign WORKS 1..N at first occurrence and reuse those numbers. Never conflate the two series. Regenerate every marker, note, bibliography entry, hyperlink, backlink and reference after EACH edit. Remove unused works or label them further reading. Verify the final PDF against the registry after pagination; resolve dangling, stale, duplicate and unsupported references. Translation editions share work IDs while keeping edition-specific reading order and supported localized note text.

## Adaptive intake and substantive length
For book and textbook, recognize a leading standalone unquoted no/-no/--no/--no-interactive token immediately after invocation; preserve later or quoted occurrences as content. Default to guided intake with at most two useful questions per round, carry forward supplied answers, allow free text/corrections/start writing, and offer fiction/nonfiction/hybrid/textbook routes. Ask for purpose/audience and desired genre/depth first when missing; adapt subsequent questions to voice, plot or research boundaries, structure, length, visual direction, language and output needs. Do not repeat answered questions or restart intake on handoff. Native supported answer controls are authoritative; never pretend static HTML receives chat events. In no mode infer reasonable defaults and proceed; report only genuinely blocking missing input. Preserve the verbatim brief and a structured editable copy.
For the prompt experience and PDF, use context-relevant generated imagery with readable live text, strong contrast, semantic typography and the user's requested visual direction. Use a supported visual surface if available; otherwise use native questions and disclose visual-surface limits. Do not block intake on decorative assets.
Build a full-length manuscript with substantial chapters, complete narrative or scholarly development and meaningful appendices. Expand through documented gap searches and counterevidence rather than filler. Keep durable checkpoints. No arbitrary length cap; stop when agreed scope is covered and targeted passes yield no material supported additions, or an actual resource/input limit is reached. Report open gaps; never claim literal exhaustive knowledge or absolute perfection.

## Design and release gates
Freeze one design contract before artwork: page geometry, safe text insets, body/display and multilingual fonts, semantic styles, colors, background treatment, citations, tables, captions, equations, footers and print behavior. Preserve the inspected source design for expound unless the user requests redesign. Explicit requested fades and 4629 art direction override legacy generic no-fade or fixed-font defaults. Canonical copyright instructions own legal text; do not copy a competing footer.
Generate actual contextual high-resolution art; record dimensions, provenance, placement, hashes and prompts. Full bleed concerns artwork; keep text within safe insets. Each required section/subsection gets a unique 16:9 banner, and distinct relevant inline images appear at least every 500 body words when that house cadence applies. Backgrounds/banners/equation plates do not count as inline images. Check exact and perceptual uniqueness. Use deterministic graphics for exact data and mathematics. Test font licensing/embedding, shaping and RTL, image ratio, readability and contrast on actual artwork.
Before release: verify requirement coverage, factual support or fiction continuity, source/citation order, compiled math and ITQE where applicable, all links/TOC/bookmarks, text selection, image coverage, and readable notes/tables. Render EVERY final page and inspect at readable resolution for overflow, clipping, overlaps, missing glyphs, background interference and footer collisions. Automated geometry/contrast scans complement this inspection. Fix and rebuild until zero unresolved critical/major defects; disclose lesser issues. Lossless optimization must preserve content, links, fonts and rendering; inspect the optimized final bytes and bind the QA record to their hash. Never declare unexecuted checks passed. If blocked, preserve editable source and label any partial output draft. Save complete deliverables persistently; report actual word/page/source counts and observed limitations.

## Executable orchestration
Run the book package `scripts/plan.py` with explicit dependency edges to order reachable declared nodes; verify prerequisites against the actual execution ledger separately. The planner does not enforce execution or prove missing phases ran; deduplication alone does not infer ordering. Establish design before artwork. Use `scripts/ledger.py` as the serialized durable operation store. Hash actual inputs/options and final artifacts, never placeholder strings. On restart inspect running entries and verify whether side effects completed; reconcile evidence before marking failed or retrying paid work. Do not clear running state automatically.
