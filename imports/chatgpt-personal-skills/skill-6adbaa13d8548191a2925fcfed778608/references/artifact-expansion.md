# Artifact expansion and per-pass QA

1. Inspect the actual source, repository instructions, architecture, dependencies, deployment, existing design, and available tests. Capture a recoverable baseline. Resolve the suffix brief against the active artifact; preserve all prior requirements.
2. Build a requirement ledger with stable IDs, acceptance conditions, implementation locations, verification evidence, and status. Distinguish shipped, partial, planned, unsupported, and blocked coverage. Maintain a gap frontier ranked by user value, correctness, security, accessibility, and feasibility.
3. Freeze a visual contract before styling: audience, navigation, task hierarchy, tokens, typography, grid, opaque data surfaces, depth, focus states, responsive layouts, reduced motion, contrast, and print/export behavior. Preserve the existing system unless explicitly redesigning. Prefer live selectable text and deterministic mathematical/data graphics.
4. Implement a coherent bounded pass. Add useful features only within the authorized product scope. Verify current official documentation and licenses before adding dependencies. Preserve determinism, original source, user edits, and compatibility. Avoid decorative complexity that hides primary controls.
5. Run technical QA on the changed revision: appropriate type checks, lint, unit/integration tests, production build, migrations, schema and import validation, security fixtures, deterministic/reproducibility tests, persistence/recovery/conflicts, authorization, exports, offline behavior, and complete user journeys. Select tests by the actual change; do not create assertions that merely mirror implementation. Record tool versions, commands, exit status, artifacts, and any baseline failures.
6. Run visual QA on that same revision: render the actual interface or artifact and inspect supported phone and desktop sizes, zoom, long/empty/error/loading states, keyboard focus, touch targets, reduced motion, contrast, overflow, math glyphs, tables, and print/export pages as applicable. Check console/network evidence when browser tools permit. Automated accessibility and text scans supplement inspection; they cannot prove screen-reader usability or correct visual rendering. Label manual assistive-technology tests NOT TESTED unless performed.
7. Repair defects before expanding again. Rerun affected technical and visual checks after fixes; invalidate earlier passes when inputs change. Do not deploy known critical defects. If a tool/access limitation prevents required checks, record BLOCKED and continue safe independent work without falsely closing the gate.
8. Checkpoint each pass with revision/hash, requirement IDs, changes, test evidence, visual evidence, defects, fixes, and remaining gaps. Persist code through the established Git workflow and other artifacts through their required storage workflow. Do not overwrite unrelated changes or expose secrets.
9. Repeat until the specified scope is satisfied or an actual blocker prevents progress. Final handoff must identify implemented counts, source/commit or review link, setup/deployment instructions, evidence, unsupported features, and unresolved gaps. Never claim production readiness from a mockup, source scan, unrun tests, or an uninspected deployment.
