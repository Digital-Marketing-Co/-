# app quality profile

Default medium: app. For inherit, use the target’s real output medium; a findings report is a separate artifact.

Exercise primary flows through UI, API and persistence; include invalid inputs, auth/authorization boundaries, isolation, reload, export, loading, empty, success, error and retry states as applicable. Run compatible typecheck/lint/build/tests and inspect relevant routes at 390, 768 and 1440 CSS-pixel widths plus keyboard/focus, 200% zoom and reduced motion. Test horizontal overflow and touch targets. A build or screenshot alone is not end-to-end acceptance. Record unavailable browser/data/auth checks as blocked.

Acceptance evidence must identify final artifact/version, check ID, required status, method, actual result and supporting evidence. Enumerate all visual units and mark each inspected. Unavailable visual tools produce BLOCKED/NOT TESTED, not PASS. Reject a finished release with unresolved defects or stale evidence.

Forward checks:
- Bare /app: ask for missing target/subject; do not invent content.
- /app no followed by a complete brief: honor explicit bypass, retain requirements and apply applicable QA.
- Repeated handoff: reuse answers, design and completed matching operations.
- Missing renderer/browser: preserve useful work and label unverified output honestly.
- Edited final artifact: invalidate old QA and inspect the new version.
