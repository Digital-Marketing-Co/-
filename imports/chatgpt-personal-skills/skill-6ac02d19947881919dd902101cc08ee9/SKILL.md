# 4629 document design

Create an awe-inspiring future-facing visual identity while preserving the document's authority, credibility, evidence, and readability. Treat 4629 as an aesthetic theme, never as a publication date or scientific credential.

## Mandatory order

1. Read the request, source artifact, supplied style references, prior answers, and applicable output skills. Preserve research scope, provenance, existing design requirements, and repository conventions.
2. Before generating artwork or implementing visual changes, present a concise **proposed style and format plan** to the user. Include the output medium and audience; page or screen structure; palette and contrast; heading/body typography; hierarchy and density; image/banner treatment; table/equation/citation treatment where relevant; depth/motion; accessibility; and print/mobile behavior. State actual defaults and explicit unknowns. Do not merely keep the plan in private working context.
3. Ask by default: **“What would you like changed stylistically or in the format? You can change the colors, fonts, layout, imagery, depth, or anything else—or say ‘use this plan.’”** Ask after the plan, never before it. Accept free text and at most two useful questions per round. Use native answer controls when suitable, otherwise ordinary chat; never simulate a functioning input form with static artwork.
4. Keep the style choice pending until the user replies. Continue independent research, inventory, content extraction, or requirements work where authorized, but do not generate decorative art, spend on design variants, freeze the contract, or implement dependent styling while the answer is pending. Silence or elapsed time is not an answer. This is preference gathering, not a new spending or publication permission flow.
5. Incorporate requested edits, state the resulting design contract briefly, and apply it. A clear edit such as “use white and gold” is enough to proceed; do not require a second generic confirmation. Ask one focused follow-up only if choices remain materially ambiguous. Honor requests to compare alternatives or revise the proposal. Later explicit style changes invalidate affected artwork/layout/export checks and require reinspection.
6. Apply the resolved contract to image prompts, banners, typography, layout, tables, equations, citations, footers, cover, navigation, and appendices. Use the actual installed content/output skills, read their instructions when used, and do not claim unavailable commands executed. Reuse already completed matching operations instead of recursively dispatching duplicate skills.
7. Render and inspect the final artifact. Repair overlaps, clipping, unreadable labels, weak contrast, distracting effects, duplicate imagery, broken links, and inconsistent treatments before delivery. For web apps inspect relevant responsive states and keyboard/reduced-motion behavior; for PDFs inspect every final page under the shared release gates.

## Plan template

Use a compact list or table, adapted to the medium:

- **Format and structure:** document size or responsive app layout, hierarchy and density.
- **Color and typography:** explicit palette, readable display/body pairing, live text and contrast.
- **Artwork and depth:** contextual distinct imagery, bleed/insets, static depth or supported motion.
- **Information treatment:** tables, equations, citations, navigation and footer as relevant.
- **Accessibility and delivery:** mobile, keyboard, reduced motion, searchable/print version and intended files.

Then ask the change question. A preview is optional; label it a draft and never make a decorative preview a prerequisite for answering.

## Visual direction

Use restrained volumetric depth, luminous edge details, translucent panels, sophisticated gradients, architectural geometry, and precisely aligned information systems. Prefer midnight navy or graphite, ice cyan, indigo, and selective warm metallic accents. Adapt to the source's tone and user preferences; avoid visual monotony and excessive ornament.

Pair expressive future-facing display typography with a highly readable body face. Keep citations and table cells comfortably readable. Use spacious hierarchy and deliberate negative space. Put data on calm opaque surfaces. Reserve dramatic treatments for covers, section openers, and meaningful emphasis.

Give each banner a distinct composition with a shared visual vocabulary. Generate imagery only with available authorized image tools. Label conceptual illustrations; never present generated scenes as documentary proof. Use deterministic tools for exact plots, maps, equations, and diagrams. Do not bake essential text into generated images.

Use static depth and lighting for PDFs. Use animation only in formats that support it, with reduced-motion behavior. Provide a white print treatment when appropriate. Retain searchable text, bookmarks where supported, logical reading order, and accessible descriptions.

## Credibility and quantitative integrity

Preserve source attribution, units, dates, definitions, uncertainty, and research limitations. Distinguish observed values, estimates, forecasts, hypotheses, and missing data. Never fabricate statistics, scholarly affiliations, credentials, or findings to make the design appear authoritative.

For global comparisons, distinguish country coverage from global completeness. Keep means and medians separate, specify denominators and weighting, and never infer a median from a mean. Preserve nominal versus real prices, currency conversions, taxes, subsidies, and purchasing-power definitions. Investigate allegations using evidence and alternative explanations rather than embedding accusations as conclusions.

Preserve equations as real typeset mathematics and tables as text. Keep evidentiary footnotes close to the relevant claims. Center one nonduplicated copyright notice per page when requested and supported by the output format.

## Acceptance criteria

Confirm the user saw the proposed style and format plan before the change question; the style answer or explicit bypass is recorded; no dependent design work occurred while the choice was pending; the resolved design specification preceded imagery and styling; every substantive section follows it; no aesthetic treatment changes factual meaning; images are distinct and relevant; tables and citations remain readable; the artifact opens successfully; and requested output files are actually saved and available. Report limitations plainly without claiming unperformed validation.
